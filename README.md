# Beze

A browser-based tool for making small 2D anime-style games. Create characters, maps,
NPCs, dialogue and simple logic visually, press Play, then download the game as a static
web build. AI will assist creation; the editor stays in charge.

## Status: slice 2

The editor runs entirely in the browser. A small Python service adds **Ask**: describe what you
want and it becomes reviewable edits to your project.

```
CREATE PROJECT → SCENE → PLAYER → MOVE → NPC → DIALOGUE → ENEMIES → PLAY → EXPORT
                                   ▲
                       "Ask" (prompt → operations) can do any of these
```

## Run it locally

Requirements: Node 22, pnpm 10, Python 3 (only for the Ask service and `scripts/generate_fixture.py`).

```sh
pnpm install
pnpm dev          # builds the runtime, then serves the editor at http://localhost:5173
```

Then: **New game** → press **▶ Play** and walk with the arrow keys or WASD. Stop, pick
**Place**, choose *Villager*, click a tile, press **New** next to "Talks" in the inspector,
edit the lines below, press **Play** again, walk up to the villager and press **E**. Place a
*Slime*, tick **Enemy**, and press **Space** near it to attack.
Walk to the horse and press **E** to ride; hold **Shift** to run. Press **+** next to Characters to
import your own sprite sheet (from any image tool): it removes the background, cuts the frames and
maps them to animations. **Export game** downloads a zip that is a static website (serve it with
`npx serve .`).

### Ask (prompt to game content)

```sh
pnpm dev:api      # needs uv (https://docs.astral.sh/uv/); defaults to the offline fake provider
```

Type into the **Ask** box at the top-right, for example "Add an NPC named Aiko who asks the
player to find a lost sword", review the proposal, press **Apply**. Undo reverts it in one step.
To use a real model, copy `apps/api/.env.example` to `apps/api/.env` and set
`BEZE_AI_PROVIDER=anthropic` with an API key, or `openai_compatible` pointing at a vLLM or
Ollama server on your own GPUs. See [docs/AI_AND_GPU.md](docs/AI_AND_GPU.md).

Other commands:

```sh
pnpm test         # unit and property tests (schema, core, runtime interpreter, editor store)
pnpm test:api     # Python tests for the generation service
pnpm typecheck
pnpm build        # runtime bundle + editor to apps/editor/dist
pnpm e2e          # Playwright: the slice, Ask, import, Hacho and Webslinger flows in a headless browser (needs pnpm build first)
pnpm schemas      # regenerate schemas/*.json from the Zod source of truth
pnpm starter      # re-render the CC0 starter art from the code in scripts/art/ (see scripts/art/README.md)
python3 scripts/generate_fixture.py   # rebuild docs/examples/hello-aiko.project.json from the starter manifest
python3 scripts/generate_hacho.py     # rebuild the Hacho template (apps/editor/public/templates/hacho/project.json + docs/examples/hacho.project.json)
node scripts/art/render.mjs --pack webslinger   # re-render the Webslinger art pack (Spidey, thugs, rooftop tiles) into apps/editor/public/templates/webslinger/
python3 scripts/generate_webslinger.py          # rebuild the Webslinger template (project.json + docs/examples/webslinger.project.json)
```

### Hacho template (a city life game)

On the projects page, **Start from a template → Hacho** creates a complete game: a top-down
Tanzanian town (64×48 tiles) with a bus station, a shop row, a market square, a bank and a
restaurant with interiors, a park, a fenced residential quarter, a locked Uptown district, six
townsfolk, missions and an economy in Tanzanian shillings. The hero is imported from a user
sprite sheet (`scripts/art/import_sheet.mjs`), the town tiles come from the City tileset
(`scripts/art/tilesets/city.mjs`) and the whole document is generated by
`scripts/generate_hacho.py`, so it can be edited in the editor or regenerated from code.

Controls (keyboard and, on touch devices, an on-screen joystick with E / RUN / ATK buttons):

| Key | Action |
|-----|--------|
| W A S D / arrows | move |
| Shift | sprint |
| E | interact (talk, open a shop, buy a property, read signs) |
| Space | attack / action |
| M | town map (discovered places, "???" for the rest) |
| I | inventory: Items, Stats, Properties, Missions |
| Esc | pause menu (inside the editor's Play, Esc with no menu open stops Play) |

The loop: explore → discover a place (+20 XP each) → talk to an NPC or business → complete a
mission → earn money and XP → buy a property → unlock a new area → take harder missions.
Missions shipped: *Welcome to Hacho*, *Lost Package* (find the parcel behind the market stalls),
*Quick Delivery* (Asha's order to the restaurant in 90 s, repeatable), *Baraka's Ball*, *Open for
Business* (buy the Small Shop) and *Uptown Access* (3 reputation stars open the gate).

Economy: you start with **TSh 50,000**; coins on the street are TSh 500; missions pay TSh 3,000 to
20,000 plus XP and, for helping people, +1 reputation. Properties pay every in-game day (2 minutes):
Small Shop TSh 250,000 → 8,000/day, House TSh 400,000 → 12,000/day, Restaurant TSh 750,000 →
25,000/day, Large Business (Uptown) TSh 2,500,000 → 90,000/day. Levels come from XP thresholds
100 / 250 / 500 / 900 / 1,400 / 2,100 / 3,000. The HUD shows money, level and XP bar, reputation
stars, the day clock and the active mission with its timer.

### Webslinger template (a spider-hero city game)

**Start from a template → Webslinger** creates a downtown of tall brick buildings (64×48 tiles), a park, a flower
market, a pizza place, a newspaper office, a bank being robbed and a warehouse run by a boss, with eight citizens,
thirteen thugs and seven missions. The hero, the thugs and the rooftop tiles are code-drawn like the starter art
(`scripts/art/packs/webslinger/`) but rendered into a **template pack** (`apps/editor/public/templates/webslinger/pack.json`
plus PNGs) that the editor loads with the template; the document is generated by `scripts/generate_webslinger.py`.

Three mechanics carry the fantasy, all data in the document (schema v4) and usable in any game:

| Feature | Where | What it does |
|---------|-------|--------------|
| **Web shooter** | `playerControl.ability = { type: 'web', rangeTiles, damage, cooldownMs, stunMs, zip }`, fired with `settings.abilityKey` (default **X**) | Shoots a line in the facing direction. The first enemy it reaches is *webbed*: frozen for `stunMs`, cannot attack, takes double melee damage. When it sticks to a wall instead, `zip` flies the player there. |
| **Wall climbing** | `playerControl.climb: true` + collision value **2** (climbable) | Cells marked 2 are solid for everyone except a climbing player, who walks over them: facades and roof ledges. Tiles carry `climbable: true` so auto-collision paints 2 (blue in the editor; the collision tool has a "Paint climbable" mode). A web shot at a wall right in front of you runs up it; across a street it grabs the next building. |
| **Danger sense** | `playerControl.senseRadius` (px) | Arcs flash over the hero's head the moment an enemy within range winds up an attack. |

Controls are Hacho's plus **X** (web). Touch devices get a WEB button. Buildings are a ring of climbable ledge tiles
around a walkable tar roof over climbable brick facades, so thugs placed on a roof stay on that roof and the hero
walks or zips up to them. Missions: *With Great Power* (tutorial), *Purse Snatcher*, *Bank Job* (three robbers),
*Pizza Time* (a 60 s rooftop delivery, repeatable), *Front Page* (three photos from the high roofs), *Rooftop
Rescue* (a guarded hostage) and *Warehouse Showdown* (3 reputation opens the door to the Enforcer).

### How a game looks (presentation)

The runtime renders at twice the document's viewport (a 480×270 game draws on a 960×540 canvas; the world camera
zooms 2× so tiles keep their size while text, panels and effects get the extra pixels). Interface text uses two
bundled OFL typefaces (Nunito for text, Bangers for titles and damage numbers) so exports work offline. Everything
below is on by default and can be turned off per project under **Project → Presentation** (`settings.presentation`):

| Feature | What it does |
|---------|--------------|
| Title screen | A night skyline (or `titleBackgroundAssetId`) under the game's title and `tagline`; any key starts. The editor's Play skips it; exports and "Quit to title" show it. |
| Lighting + day/night | Phaser Light2D on tiles and sprites. The ambient colour follows the world clock (the economy's day, or `dayLengthMs`, opening at `startHour`). Tiles tagged `lamp`, `sign_*` and friends (`lampTags`) become lights at night; a `light` component puts one on any entity. |
| Bloom and vignette | Post-effects on the world camera. |
| Cards and transitions | Letterboxed cards for new/completed missions, discovered places and level-ups; camera fades between scenes; defeat drains the colour and slows time. |
| HUD | Portrait, hearts, money, level and XP bar, reputation, a day clock with sun/moon, the active mission with its timer, an ability cooldown chip, key-cap prompts. |
| Quality | `auto` turns the lights and post-effects off on software renderers (headless test browsers, VMs) so the frame rate, and with it the physics, stays at speed. Hosts can force it with `window.__BEZE_QUALITY` or the runtime's `quality` option. |

### Sound

Sound effects are synthesized in the runtime from a table of parameters (`packages/runtime/src/audio/synth.ts`, in
the spirit of sfxr): web shots, punches, hits, coins, discoveries, mission fanfares, menu blips, the typewriter. No
files, deterministic, works offline. Music is generated too (`audio/music.ts`): a mood sets tempo, key and chord
progression, bars are composed on the fly, and the drums, arpeggio and lead join when enemies are close. Moods:
`city`, `night`, `calm`, `tense`, `title`; `auto` plays city by day and night after dark (calm without an economy).
**Project → Sound** picks the mood and volumes or uploads an OGG/MP3 track instead; a scene can override both
(`scene.music`, `scene.musicAssetId`). Menus and dialogue duck the music.

## Layout

| Path | What |
|------|------|
| `packages/project-schema` | Zod schemas, TypeScript types, `parseProject`, migrations, JSON Schema export |
| `packages/project-core` | `applyOperations` with total inverses, integrity validator, limits, project factory, recipes, export bundle layout |
| `packages/runtime` | Phaser 3 interpreter for project documents; builds one IIFE used by both the editor's Play iframe and exports |
| `apps/editor` | React editor: Canvas 2D viewport, tools, inspectors, list-based dialogue editor, Ask panel, sandboxed Play, IndexedDB persistence, zip export |
| `apps/api` | FastAPI generation service: prompt → operations, provider adapters (Claude, OpenAI-compatible for self-hosted GPUs, fake) |
| `schemas/` | Generated JSON Schema for the document and the operation catalog (the AI tool definitions, later) |
| `scripts/` | Starter art pipeline (`art/`, code-drawn, rendered by `render.mjs`; `art/packs/<template>/` for template packs) and the fixture/template generators |
| `docs/` | Architecture and the slice spec |

Read [docs/FOUNDATION.md](docs/FOUNDATION.md) for the architecture and
[docs/VERTICAL_SLICE.md](docs/VERTICAL_SLICE.md) for the slice's scope and acceptance criteria.
`docs/examples/hello-aiko.project.json` is the golden fixture the runtime and tests use.

## Shape of the system

```
Editor (React, Canvas 2D)  ──operations──▶  Project document (JSON, Zod-validated)
        │                                            │
        │ Play (sandboxed iframe)                    │ Export (copy runtime + json + assets)
        ▼                                            ▼
Runtime (Phaser, interprets the document)   Static web build
```

Backend so far: the FastAPI generation service. Next: accounts, saved projects, assets and
exports on PostgreSQL and S3-compatible storage, per `docs/FOUNDATION.md`.
